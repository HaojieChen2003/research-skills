# Windows 独立作业：协议草案与验收

状态：2026-11-15写入技能的设计。目标接口尚未由本技能实现或验证；不能向其他agent声称命令可用、队列已部署或可保证恢复。现有windows_remote.py用于接入，不等于本协议的作业调度器。使用前检查项目实际工具和当前设备。

## 工作方式

Mac准备/提交 → Windows本地独立运行 → 用户可让Mac离线 → 用户回来后查询并回传结果。提交不依赖持续SSH或Mac挂载目录。科学参数与验收由numerical-experiment管理，此处只负责作业生命周期、身份、资源和传输。

原生Windows用PowerShell本地启动器与计划任务；Mac上的Bash只是客户端包装。无需先部署Slurm或WSL。未来实现可以使用Python统一客户端，但必须沿用实际存在且测试通过的入口，不能照抄下列占位命令。

## 目标动作（不是当前可执行命令）

| 动作 | 应有语义 |
|---|---|
| submit(job specification) | 验证路径/输入、准备快照、申请资源、独立启动或排队，返回唯一job_id及回执 |
| status(job_id) | 读回执/状态，必要时核查同一任务进程；区分执行和验证，说明核查时刻 |
| logs(job_id) | 有界读取日志尾部或指定范围，不默认下载大日志 |
| fetch(job_id) | 拉回约定产物并核对身份/哈希；未完成阶段明确标partial |
| cancel(job_id) | 在已授权范围核对并取消该任务及其子进程，确认已退出；不影响其他作业 |

不默认提供shutdown、自动重试或重启恢复。需要这些能力时分别定义授权、幂等和检查点语义。

## 作业说明与身份

作业说明与科学配置分开。最小字段：project_id、request_id、name、entry、config、input inventory、resources.processes、resources.threads_per_process、可选memory预算、walltime预算、输出根目录。使用JSON或项目已支持的格式，不因示例是YAML就增加依赖。

从实际项目配置解析本地/远端根目录、解释器、工作目录和主机选项，不固定示例项目路径、用户名或任务名。运行记录保存config内容、输入/代码哈希、环境、命令及调度设置。参数通过结构化数组/文件传递，不能把不可信路径拼成PowerShell/cmd表达式；路径含空格需实测。

request_id是提交幂等键，job_id是运行唯一身份。同一request_id重试时返回原回执或明确说明不一致，不能再开一份计算。内容相同但request_id不同可以是用户有意复算，不自动禁止。SSH超时时先查是否已受理；无法确认时报告待核实，不盲目重提。

## 目录与写入

按项目已有规范：通用工具留共享skill或项目设备工具目录；科学入口留Code，作业资源配置留Parameters/windows（或项目等价位置），结果/日志/状态进入独占实验运行目录；传输中间文件用设备Temporary/<任务ID>。不能每个任务复制并长期维护一套求解核心。

先在独立暂存目录完整传输并校验，再标记ready。源码/配置使用不可变快照或固定工作副本，运行期间其他agent更新项目不应改变本次对象。回执至少含job_id、request_id、project_id、主机、任务名、运行目录、配置/代码身份、提交时间与状态/日志位置。临时清理前保留完成查询和回传所需回执，不依赖某个聊天进程的内存。

## 独立运行与资源

计划任务调用Windows本地启动器，启动器写开始/终态、退出码和异常，Python采用不缓冲日志。启动验证沿用SKILL.md的断开后复查规则；提交accepted/queued不等于running。短任务复查时可能已结束，此时核对完整终态和结果，不误判为启动失败。

默认单个重载作业运行，其余排队的能力只有实现统一调度后才能宣称支持。实现时设备级唯一调度器/原子资源领取必须覆盖所有合作项目与agent；仅客户端各自检查CPU空闲不防竞态。已在运行的外部任务也计入预算，不自动停掉或纳管。尚无可靠队列时明确说明，重载任务不并发冒充排队。

进程×线程与内存共同计入资源；环境变量在数值库导入前设置。walltime若仅被记录而未实施停止，必须称预算而非硬限制；实施时只作用于本任务进程树并保存停止原因。检查任务的登录模式、运行时限、空闲/电池停止及设备睡眠条件；无授权不更改系统电源策略。

## 状态和交接

execution：prepared/queued/running/completed/failed/cancelled/interrupted等按真实实现映射；validation独立为not_checked/passed/failed或详细子项。不能以计划任务Ready、退出码零或没有进程直接写completed。

status保存job_id、stage、done/total及单位、开始/更新时间、已用时间、退出信息；单写入者原子替换。增量结果与partial/completed标志配套。ETA按近期代表性工作量估算，阶段变化需重估，不用固定块数推总时间。无新进度时标出最后更新时间。

确认独立运行后交接任务号、阶段/核查时刻、估时范围、日志/结果位置、Windows需保持的条件。用户可合Mac，不需要保持SSH。用户选择稍后查询时不轮询、不承诺离线主动通知或自动拉回。

## 后续测试：仅在用户明确允许且不影响重要任务时执行

1. 本地离线验收：检查schema、路径/参数转义、唯一ID和重复request语义，不能将静态检查称为远端通过。
2. Windows空闲时用短小非科研作业：确认提交、带时间戳日志、原子状态、退出码及快照身份；断开SSH后重新查进度或完整终态。
3. 两个小任务验证排队/资源领取；同request重提确认不重复执行。故意失败检查failed与异常；取消仅本任务，并确认子进程退出。
4. fetch核对文件清单/哈希；客户端重启后仍能凭job_id查询。测试中断/恢复时不要求Windows重启，除非另有授权；无检查点则明确从头重跑。
5. 再用受控科研小算例核对与既有运行的矩阵/场一致。日志、协议版本和已测/未测能力留证，随后更新本文件状态。

测试未完成前保留现有已验证的手工计划任务方式，不替换正在运行的任务，也不把草案命令发送给用户作为可直接运行方案。
