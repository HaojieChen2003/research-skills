# 数值实验与代码维护

从当前方程和实际参数入口执行用户的实验，不用替代方程或替代参考解完成原任务。

## 明确实验
实验设计、运行说明与结果分析必须先定义后使用：先明确所求量、指标集、参数与单位、方法缩写、参考解及误差范数的含义，再列公式、配置和数据；区分物理量与为实现引入的派生量，说明对应关系。

按 [严格控制变量](references/controlled-experiments.md) 确定研究问题、唯一研究因素、固定因素、参考解和误差定义。可从上下文恢复的信息直接核对；关键歧义才询问。单纯分析已有数据不自动启动新计算。

## 维护与参数
- 数值核心保留一份，共享基、求积、装配、重构等函数；steady/unsteady/test 只承担相应模型与实验入口。遵守项目已有架构，不为符合模板而重建目录。
- 物理、空间、时间、求积、精度、求解器、线程和输出参数由独立参数表加载。检查实际加载路径、默认值和覆盖项，并保存最终生效配置。
- 已产生结果的配置作为不可覆盖的实验快照；新设置创建新配置/运行目录。不要把整个论文项目的旧默认配置当作当前实验。
- 重构前选一个小而有辨识力的算例，比较矩阵、载荷及重构场。保留数学意义、索引顺序、dtype、边界处理与参数语义；确需改变时显式说明。

## 调用、身份与长任务分块
- 跨模块调用前读实际函数签名、类定义及返回结构，不猜属性名。会改变数学对象、分支、精度或额外计算的关键参数显式传入并记录；无需把所有无关默认参数机械展开。
- 适配入口优先复用共享核心；确需绕开既有装配时，明确等价范围，用已知小算例核对矩阵、载荷或场，不仅核对退出码。
- 身份采用输入/配置内容哈希及显式逻辑键，路径另记为位置；绝对路径、项目外配置也须能记录。相对路径解析和内容身份分开处理，不为记录relative_to而使有效计算失败。
- 大文件先搜索定位再范围读取；查数据先读目录索引和小型元数据，按问题读取数组切片，不整库加载。
- 大规模点云、压力核或并行分块任务，读取 [分块与估时](references/chunking-and-progress.md)。

## 执行与交付
设备按用户偏好、代表性实测、环境和资源选择；不要默认所有研究者都有Mac/Windows，也不设通用的十分钟分界。

先小规模试运行获得时间和峰值内存，再说明外推依据。用 research-compute-access 连接其他机器；运行器保持在项目中。记录代码标识/哈希、依赖版本、输入哈希、生效参数、命令、开始时间、进度、失败和输出位置。后台任务采用可续算的独立运行目录及状态文件，不把 SSH 连接存活当作任务存活。

估时样本应尽量保留正式运算的批量形状、缓存和线程方式；逐点耗时线性外推不一定代表批量核计算。给出估算范围，完成后保留实测与估算的差异。不要为低成本的一次性验证强建续算框架；只有长任务或恢复成本值得时增加检查点。

诊断程序复用共享数值核心；先用基准组核对已有矩阵、载荷或场，证明诊断本身未改变对象。预算停止后标记未完成算例，不能将部分完成报告为整组完成。

分别报告 execution 状态和 validation 状态。读取数据中的 NaN/Inf、缺项与失败标志；无效参考解不能参与误差。重构完整场后计算指定空间中的误差；输出有效位数遵循任务。结论只覆盖已计算的模型和范围。诊断异常用 numerical-diagnosis，制图用 research-figures，发布到论文用 manuscript-maintenance。

辅助工具：`scripts/experiment_records.py compare A.json B.json --vary space.radial_orders --ignore name --ignore output` 检查两个配置；`fingerprint FILE...` 输出输入/代码 SHA256。工具只作结构比较，不代替实验设计。
