## 1. 基本检查

在推导前明确：

- 研究对象及其类型；
- 变量、定义域与参数范围；
- 已知条件与目标；
- 使用的额外假设；
- 结论是精确、近似、局部还是全局。

必要时区分 `【定义】`、`【已知】`、`【假设】`、`【推导】`、`【结论】`、`【验证】` 和 `【不确定】`，但不要把标签变成固定装饰。

## 2. 定义与定理

先定义后使用是硬性要求：符号、变量/指标的范围、集合、函数空间、算子及其作用对象、物理量和单位必须先于后续使用明确给出。派生量解释定义式与引入用途，不能仅凭名称或文献引用让读者猜测。修改叙述次序后按首次出现位置复核。

解释定义时说明对象与适用范围；正例、反例或边界例仅在帮助理解或辨别条件时加入，不要求每个定义机械配例。

陈述定理时分开写条件与结论。说明关键条件为什么必要；删除条件会导致失败时，给出最小反例。

直觉用于帮助理解，不能代替严格定义。

## 3. 推导与证明

允许压缩机械计算，但不能省略：

- 等价变形的依据；
- 定理调用条件；
- 分类讨论的完备性；
- 除法、开方、取对数等操作的合法性；
- 极限、积分、求和或微分交换的条件；
- 存在性、唯一性和收敛性；
- 量词顺序及充分、必要关系。

检查证明时优先定位第一个使后续推理失效的步骤。先解释为什么失败，再给最小修正；用户要求时再给完整重写。

第一性原理分析采用：

```text
定义 → 最简单情形 → 结构或不变量 → 一般化 → 边界检查 → 验证
```

不要把博弈论、成本收益等框架机械套入普通数学推导。

## 4. 解集与边界

方程、不等式、极值、微分方程和参数问题至少检查：

- 增根与漏解；
- 原定义域；
- 参数区间是否覆盖；
- 边界点；
- 局部解与全局解；
- 存在性与唯一性。

## 5. 验证

按命题选择有辨识力的核对方式；需要证明时补足逻辑论证，抽样或符号检查只作辅助，不以方法数量代替证据强度：

1. 代回原式；
2. 反向推导；
3. 特殊值或极端情况；
4. 量纲检查；
5. 数值抽样；
6. Python 或符号计算；
7. 与已知定理对照；
8. 构造反例。

明确说明验证支持什么，以及它不能证明什么。

## 6. 高风险行为

不得：

- 将有限样本或图像观察当成证明；
- 默认逆矩阵、极限、最优解或级数性质存在；
- 未经说明交换极限、积分、求和或微分；
- 忽略定义域、量词或边界；
- 把相关性写成因果性；
- 用模糊自信掩盖信息不足。

不确定时明确写出目前可确认、尚不能确认以及需要补充的条件。
